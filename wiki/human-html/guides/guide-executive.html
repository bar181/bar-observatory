A guide for executives, clients & managers

What did I actually pay for?

No terminal, no code reading, no jargon required for this page.

You commissioned AI-assisted work — from a vendor, a contractor, or your own team. At the end, you got a confident summary: it's done, it works, here's what we built. That summary was written by the same AI that did the work. This page is about the difference between that summary and a record you can actually check.

The situation

You can't verify a summary. You can verify a record.

An AI coding agent working on a real task does hundreds of things — reads files, runs commands, tries something, fails, tries again, hands work to helper agents you never see. Then it writes you a paragraph: "Completed successfully." That paragraph is a claim, not evidence. It's written by the party being evaluated, about its own work.

This isn't a trust problem specific to AI — it's the same reason an invoice isn't the same thing as a receipt, and a project update isn't the same thing as an audit. The difference is that a human contractor's work leaves other kinds of evidence around it. An AI agent's work leaves almost nothing unless something specifically captures it — which is the entire reason this tool exists.

Cost 01

You can't tell effort from padding

Was that a genuinely hard problem, or did the agent circle back on the same file 150 times because the spec was unclear? Both look identical from a summary alone.

Cost 02

Failures don't reach you

A timeout, a blocked command, a retry loop — these scroll past in a terminal window nobody hands you. You only hear about the ones the agent chose to mention.

Cost 03

Nothing to attach to a decision

Sign-off, invoicing, a client update, a post-mortem — all of these want an artifact. "The agent said it went well" isn't one.

The guide

Think of it as an itemized receipt for the work.

BAR Observatory doesn't ask the agent what happened. It reads the actual record the session left behind — every tool call, every failure, every retry — and turns it into a report. Not a summary written by the party you're evaluating: a calculation over what was actually recorded.

"0 failures" means the report looked at the evidence and found none.
"Not recorded" means the report didn't have enough evidence to make that claim at all. The single rule that makes the rest of this trustworthy

That distinction matters more than it sounds. A tool that quietly turns "we didn't check" into a reassuring zero is worse than no tool — it's a false sense of certainty with your name on the sign-off. BAR Observatory says plainly when it doesn't know something, the same way a good accountant flags "unable to verify" instead of guessing a number that looks fine.

What you'd actually receive

A report built for you, and a separate one for whoever maintains this.

You shouldn't have to read a technical timeline to get an answer, and your engineering team shouldn't have to read a client memo to get one either. BAR Observatory produces both from the same underlying facts, so they can never quietly disagree with each other:

Calculated (always available, $0.00)Interpreted (optional, written)
For youThe full itemized record — every claim traces to a real rowA consulting-style memo: what was delivered, what it cost, what risks surfaced
For the engineersThe chronological technical timeline, every failure, every rework hotspotWhy the run went the way it did, and what to change next time

The calculated report is the evidence. The interpreted one is commentary written about that evidence — always labeled as such, and the underlying facts never depend on it existing.

What this requires from you

Nothing technical. That's the point.

  • You don't run anything. Whoever is doing the AI-assisted work — your vendor, your contractor, your own developers — installs a free, open-source tool. You just receive the report.
  • You don't need an account, and neither do they. No sign-up, no subscription to this tool specifically, no data handed to a third-party service.
  • Nothing about your project changes. No code is added to what's being built. The tool watches the AI session, not your product.
  • It works after the fact, too. If a session already happened and nobody was recording, a report can often still be generated from the transcript that's already sitting on disk.
The one honest exception. If you ask for the optional written narrative (the "interpreted" report), that step uses an AI model to write the prose — clearly labeled wherever it appears. The itemized, calculated report never depends on it and never involves a model itself.

Questions you'd actually ask

Before you ask your team to set this up.

Is this a compliance certification I can point to?

No, and it doesn't claim to be. Reports are reproducible and consistent — the same underlying record always produces the same report — but that's an engineering property, not a legal one. If you have a specific regulatory or evidentiary requirement, check it against what you actually need.

Does this cost anything?

The tool itself is free and open-source, and stays that way — the license doesn't allow that to change retroactively. Whoever runs it (your team or vendor) bears only their own normal development time.

Can a vendor just turn this off before the parts that make them look bad?

A vendor could choose not to run it, the same way they could choose not to send you an invoice. What this tool prevents is a different failure mode: an agent session that was recorded quietly showing you a flattering summary instead of the real one. If you want the guarantee it provides, ask for the report as a deliverable up front — the same way you'd ask for anything else you expect to receive.

What if I want the technical detail myself?

You can — the full report is available to any reader, and the plain language walkthrough of how to get one at all is here: wiki/human-md/README.md.
